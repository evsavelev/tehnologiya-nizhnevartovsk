# Технология — корпоративный демо-каталог

Демо рекламно-производственной компании из Нижневартовска. 21 статическая страница: главная, каталог, шесть категорий, пять услуг, портфолио с 12 работами, три кейса, производство, о компании, новости из официального VK, контакты. Все прежние 19 адресов сохранены.

Фирменное обновление: графитово-бронзовые панели с самостоятельным SVG-мотивом по визуальному языку VK-обложки. Каталог и текстовые разделы остаются светлыми. Клиентский сценарий и выводы проверки — `CLIENT-REDTEAM.md`.

Публичный адрес: https://evsavelev.github.io/tehnologiya-nizhnevartovsk/

## Локальная работа

Node.js 24. В PowerShell используйте `npm.cmd`, если запуск npm.ps1 запрещён политикой Windows.

```sh
npm ci
npm run build
npm start
# В другом терминале:
npm test
node scripts/seo-check.cjs
# Разовая проверка доступности исходных постов VK (требует интернета):
node scripts/verify-vk.cjs
```

Открыть http://127.0.0.1:4173/tehnologiya-nizhnevartovsk/. QA использует установленный Google Chrome. Скриншоты и машинный отчёт сохраняются в `qa/` (не публикуются). Для проверки опубликованной версии задайте `QA_URL` с завершающим `/`.

## Архитектура и контент

- `data/catalog.js` — категории, варианты, услуги и связи с проектами.
- `data/projects.js`, `data/news.js` — портфолио и фотообзоры.
- `data/company.js` — контакты; `data/media.json` — происхождение фотографий.
- `data/catalog-guidance.js` — исходные данные для расчёта в каждом направлении.
- `src/components.js` — переиспользуемые компоненты и URL конфигурация.
- `scripts/build.js` — сборка HTML, метаданных, sitemap и 404 в `dist/`.
- `src/styles.css`, `src/app.js` — адаптивная сетка, меню, галерея, фильтры, mailto.
- `DESIGN.md` — утверждённое направление и дизайн-ограничения.
- `QA.md` — результат проверки и ограничения.

Чтобы добавить услугу, внесите объект в `services`, укажите её ID в категории и связанные проекты, затем пересоберите. Новые категории автоматически получают страницу. Подробный кейс создаётся для проекта с `page: true`. Для смены домена измените `base` и `origin` в компонентах, пересоберите и проверьте ссылки/canonical/sitemap.

Связи категории с услугами вычисляются из поля `category` каждой услуги. Для предметной перелинковки задайте `relatedServices` в таблице `related` в `data/catalog.js`. Формат сохраняет три уровня каталога; при расширении добавляются данные и связи, а не копии HTML-шаблонов. Для сотен позиций следующим этапом можно добавить подкатегории и постраничный вывод, после согласования структуры с компанией.

## Ручное обновление новостей

Новости редактируются в `data/news.js` и собираются на главной и `/news/`. Для записи нужны уникальный `id`, заголовок, короткий пересказ, прямая `vk`-ссылка вида `https://vk.ru/wall-179232832_...`, реальный `imageFile` с размерами либо номер существующей фотографии `image`, содержательный `alt`, тематическая `category` и при наличии `project`. `dateLabel` заполняется только датой, видимой в источнике; относительные даты не пересчитываются. `sourceNote` и `verified` служат для редакторской проверки и не выводятся посетителю.

Проверить публикацию и принадлежность фотографии, сохранить изображение локально и записать происхождение в `data/media.json`, затем собрать, проверить и отправить изменения. Никакой API-интеграции, автоматического импорта, фоновой синхронизации или CMS нет. `scripts/verify-vk.cjs` только проверяет доступность уже выбранных ссылок и не изменяет контент.

Форма не отправляет данные на сервер: формирует mailto, пользователь отправляет письмо в почтовой программе. Никаких аналитических счётчиков, регистрации, загрузки файлов, корзины или оплаты нет.

## Публикация

GitHub Pages из GitHub Actions. Каждый push в `main` запускает `.github/workflows/pages.yml`, собирает только публичный каталог `dist` и публикует его. Исходные материалы клиента, локальные инструменты, credentials и QA-скриншоты не входят в артефакт сайта.

`robots.txt` подготовлен в папке проекта. На GitHub Pages project site правила обхода определяются корневым `/robots.txt` домена; файл внутри `/tehnologiya-nizhnevartovsk/` не заменяет его. При переносе на собственный домен разместить файл в корне. Sitemap и canonical уже используют публичные адреса страниц.
